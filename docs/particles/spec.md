# 粒子の層(`src/scene/particles.js`)の確定仕様

`docs/technical-design.md` の「5. 描画」のうち、粒子の決めごとを確定したものです。設計文書と食い違うところは、この文書が優先します(変更点は末尾の「設計文書からの変更」にまとめました)。

同じフォルダのファイル:

| ファイル | 内容 |
|---|---|
| `particles-final-glsl.js` | 頂点シェーダ `PARTICLE_VERT` とフラグメントシェーダ `PARTICLE_FRAG`。前に `GLSL_ARC` を連結して使う |
| `reference.js` | シェーダと同じ計算の JS 版(ハッシュ、弧の長さ→t、枠の予算、枠の並べ替え、位相)。実装とテストの土台 |
| `check.mjs` | `reference.js` をデータで確かめるスクリプト。`node check.mjs public/data/od.json` |
| `hashcheck.cjs` | GLSL のハッシュと JS のハッシュが一致することを、Playwright の WebGL2 で確かめるスクリプト |
| `arclen.py` | 弧の長さ→t の変換式と定数の導出。`python3 -I arclen.py`(numpy が必要) |
| `strip.py` | 年の補間中の粒子の並びのシミュレーション(`shots/strip_*.png` の3本を作る。`shots/year_transition_strip.png` はこれを縦に並べたもの) |
| `shots/` | 推奨の画面と、判断の根拠になった比較 |

## 1. 決めごとの要点

- 1粒が100人です。粒子は弧の曲線の**上にそのまま**置きます(管の中へ散らしません)。
- 粒子の位置は**弧の長さ**で決めます。B スプラインの媒介変数 t を一様に進めると、粒子が両端に溜まります(t が 0〜0.2 の範囲は弧の長さの 4.4% しかなく、粒子の4割が長さの 8.8% に集まります)。
- 大きさは 2.5 CSS px、不透明度は 0.5 です。全国表示で近距離の量の多い流れが飽和するのは「濃く太い線」として受け入れます。
- 品質の基準: 粒子1つが100人を表し、粒子の数・大きさ・不透明度を視覚効果で変えません。

## 2. 枠の予算と属性

- 弧(o→d、o≠d、2,162本)ごとに、全年の `ceil(v / 100)` の最大を枠の数とします。2012〜2025年の**合計は 26,206 枠**です。
- 参考(t11.xlsx から集計):
  - 弧ごとの枠数は、最大 887(東京→神奈川)、中央値 3、平均 12.1、90パーセンタイル 25、99パーセンタイル 132 です。
  - 全年とも100人未満で1枠だけの弧は 560 本です。人数0の弧はありません。
  - 年ごとの人数÷100 の合計は 21,483(2025年)〜23,347(2015年)、`ceil(v/100)` の合計は 22,594〜24,459 です。
  - 100人未満の弧は、年により 666〜735 本です。
- 属性は `aSlot: vec3 = (o, d, k)` の1つだけです。`Float32Array(26206 * 3)` で 314KB です。k は弧の中の0始まりの番号です。
- three.js の `Points` は `position` 属性の数で描く頂点の数を決めます。そのため、使わない `position`(`Float32Array(total * 3)`)も付けてください。
- 枠の数は年や視覚効果で変えません。負荷が高いときも減らしません。

## 3. 人数テクスチャ

- **形式は R32F、幅 47、高さ 47 × 年数(14年で 658)です。** 大きさは 123KB です。
- 作り方: `new THREE.DataTexture(data, 47, 47 * NY, THREE.RedFormat, THREE.FloatType)` とし、`internalFormat = 'R32F'`、`minFilter = magFilter = NearestFilter`、`generateMipmaps = false`、`needsUpdate = true` にします。
- `data` は od.json の `matrices` を年の順に連結したものです(`reference.js` の `countsTextureData`)。
- texel `(d, 年の添字 * 47 + o)` が、o から d へ移った人数です。
- 整数は 2^24 まで正確なので、最大値 82,030 も誤差なく渡せます。幅 2,162 の並べ方は使いません。WebGL2 で保証される最大テクスチャ幅が 2048 だからです。
- 読み出しは `texelFetch` を2回行い、`mix(vA, vB, uYearMix)` で補間します。年の添字は `uniform int uYearA, uYearB` で渡します。
- 同じテクスチャは、弧の層やツールチップからも使えます。

## 4. 位置

### 位相

```
r_arc = u01(o * 47 + d)                 // 弧ごとの乱数
g     = fract(k * 0.618034 + r_arc)     // 黄金比の並び
s     = fract(g + uPhase)               // 動きあり
s     = 0.04 + 0.92 * g                 // 動きを減らす設定(静止)
t     = arcT(s)                         // 弧の長さの割合 → B スプラインの媒介変数
```

- `u01` は整数のハッシュ(lowbias32)から作る [0, 1) の値です。GLSL 版と JS 版の式は `particles-final-glsl.js` と `reference.js` にあります。GLSL 版と JS 版の結果は、id 0〜4095 で一致することを確かめました(`hashcheck.cjs`)。
- `uPhase = fract(timeSec / 14)` です。CPU で倍精度で計算して渡し、生の秒数をシェーダに渡しません。流れる時間はすべての弧で 14 秒です。

### 弧の長さ→t の変換(`arcT`)

すべての弧は相似な曲線です。制御点 `[A,A,A,M,B,B,B]`、M の高さは `K × 弦` です。そのため、1つの式ですべての弧に使えます。

```
C = 5.510779, S0 = 0.0861059
s < S0     : t = (s / C)^(1/3)                     // 区間0([A,A,A,M])は直線で、s = C t^3 が正確に成り立つ
s > 1 - S0 : t = 1 - ((1 - s) / C)^(1/3)
それ以外   : x = s - 0.5
             t = 0.5 + x (0.52318546 + x² (0.0844248 + 2.19156312 x²))
```

- 精度は、t の誤差で 0.00085 以下、弧の長さに換算して 0.00087 以下です。S0 での段差は t で 0.00085 です。
- 弧の長さは弦の 1.0411 倍、最高点の高さは弦の 0.1322 倍です。
- 導出は `arclen.py` で再現できます。

### 曲線上の点

- 弧の式の評価は、粒子1つにつき1回です。
- `arcPoint` をシェーダの中で展開して書き、`nodePos` の読み出しを2回に抑えます。4区間のうち t が属する区間の B スプラインだけを評価します。
- `side`、`lean`、`morph` の扱いは弧の層と同じです(技術設計 4章)。真横の定位置(morph = 0、lean = 0)では、粒子は原作の arc diagram の曲線の上に乗ります。

## 5. 不透明度

```
w     = clamp(n - k, 0, 1)                                   // n = 補間後の人数 / 100
alpha = 0.5 * w * smoothstep(0, 0.04, s) * smoothstep(1, 0.96, s)
```

- Σk w は、どの年・どの補間の途中でも、ちょうど人数 / 100 になります(`check.mjs` で確認済み)。
- 端の薄めは、t ではなく**弧の長さの割合 s** で測ります。
- フラグメントシェーダでは、直径 `uSize` の円を1pxの縁でなめらかにして描きます(`gl_PointSize = uSize + 1`)。
- 合成は通常のアルファ合成です(`transparent: true`、`depthTest: false`、`depthWrite: false`)。

## 6. 年の補間

- `setYear(a, b, mix)` では、`uYearA`、`uYearB` に年の添字を、`uYearMix` にイージング済みの値を渡します。何年も離れた年へ移るときも、2つの年を直接補間します。
- 黄金比の並びでは、新しく現れる粒子は常にそのときの最大の隙間に入ります(n = 2〜899 で 898/898)。隙間の最大と最小の比は 2.63 以下です(厳密な φ では φ² = 2.618)。
- 既にある粒子は動かず、番号の大きい粒子から、その場で薄れて消えます(`shots/year_transition_strip.png` の上段)。
- 切り替えの時間の目安は 0.8 秒、ease-in-out です(実時間の見え方は未検証)。動きを減らす設定では、即座に切り替えます。

## 7. 地上と地下の描き分け

- 描く順序は、地下の弧、地下の粒子、地面と境界線、地上の弧、地上の粒子です。粒子は `uPass`(−1 が地下、+1 が地上)を変えた2つの `THREE.Points` で描きます。
- 選択の状態が変わるたびに、CPU で枠を [地下 | 地上] の順に並べ直します(`reference.js` の `orderSlots`)。
  - 選択地域の内部どうしの弧と、選択地域に関わらない弧は、この並べ替えで除きます。
  - 2つの `BufferGeometry` で同じ `aSlot` 属性(と使わない `position`)を共有し、それぞれに `setDrawRange(start, count)` を設定します。
  - 並べ替えたら `attribute.needsUpdate = true` にします。
- 頂点数は、全国表示で 地下 12,803 + 地上 13,403、東京圏選択で 4,106 + 5,189 です(`check.mjs`)。
- シェーダの中の `side` と `vis` の判定は保険として残します。並べ替えをしなくても、正しく描けます。
- `frustumCulled = false` にします。
- `side` の規則は技術設計の `sideOf` と同じです。全国表示では o > d が地上、選択中は選択地域への転入が地上です。

## 8. 動きを減らす設定と `still=1`

- 動きを減らす設定では、`uStill = 1`、`uPhase = 0` にします。並べ方は `s = 0.04 + 0.92 * fract(k * 0.618034 + r_arc)` です。
  - すべての枠が [0.04, 0.96] に入るので、端の薄めでインクが減りません。
  - 年を切り替えても、既にある点は動きません。`(k + 0.5)/n` の並べ方は、`ceil(v/100)` が変わるたびに全点が並び替わるので使いません(`shots/year_transition_strip.png` の中段)。
- `still=1` では時間を固定し(`uPhase = 0`、または URL の時刻から求めた値)、動きを減らす設定に合わせます。
- 乱数はすべてシェーダの中で (o, d) のハッシュから作り、`Math.random` を使いません。そのため、同じ引数と同じ画面の大きさ・DPR なら、画素まで同じ結果になります。
- Canvas 2D の代替表示は、`reference.js` の `slotS`、`arcT`、`slotWeight`、`endFade` で同じ点描を描けます。

| 名前 | 値 |
|---|---|

| 枠の総数 | 26,206(弧ごとに全年の `ceil(v/100)` の最大) |
| 粒子の大きさ | 2.5 CSS px(`uSize = 2.5 * DPR`、`gl_PointSize = uSize + 1`) |
| 粒子の不透明度 | 0.5(ライト・ダーク共通の初期値) |

| 端の薄め | s が 0〜0.04 と 0.96〜1 で smoothstep |
| 静止の配置 | `0.04 + 0.92 * fract(k*0.618034 + r_arc)` |
| `arcT` | C = 5.510779、S0 = 0.0861059、c1 = 0.52318546、c3 = 0.0844248、c5 = 2.19156312 |
| ハッシュ | lowbias32(0x7feb352d、0x846ca68b)、`u01 = (h >>> 8) / 2^24` |

## 10. 確かめたことと確かめていないこと

試作(three.js 0.186.1、Chromium + SwiftShader)とスクリプトで確かめたこと:
- 枠の予算と分布(t11.xlsx から集計)。
- R32F の人数テクスチャを `texelFetch` で読み、2つの年を補間して描けること。
- 弧の長さでの並べ直しの効果。画面に見えるインクが真横で +38%、斜め俯瞰で +30% になり、節点の塊が解けました。
- 管との比較。全国表示では首都圏が形のない黒い雲になり、選択時や拡大時は弧がぼやけるだけでした(`shots/compare_*`)。なお、管の向きを水平だけにすれば真横の画面は変わらないことも確かめました(画素一致)。
- 大きさと不透明度の比較。2.5px・0.5 で、濃淡の段階が最もよく出ました。2.2px・0.8 は粗く、1.6px・0.5 は遠距離の粒子が薄すぎました。
- 重なりによるインクの損失。斜め俯瞰の全国表示で、画面に見えるインクは理想値の約5割です。「インクの総量が人数に比例する」は粒子1つずつの約束で、重なった画素では成り立ちません。
- 年の補間中の粒子の増減(`strip.py` のシミュレーションと静止画)。Σw = 人数/100 の成り立ち。黄金比の隙間の性質。
- `still=1` の再現性。別々に2回読み込んだ画面は画素が一致し、`still=1` で time=0 と time=7 の画面も一致しました。
- GLSL のハッシュと JS のハッシュの一致(`hashcheck.cjs`)。
- 負荷(SwiftShader、1200×600)。2回描画でそれぞれ全枠を処理して、粒子だけで 39〜52 ms/フレーム、DPR 2 で 65 ms でした。弧の長さの並べ直しによる増分は測れないほど小さく、弧の線の層だけで 358 ms でした。

確かめていないこと:
- 実際の GPU での負荷。見積りは、1頂点あたり texelFetch 4回とスカラー演算 約110〜130回です。並べ替えありで 26,206 頂点、約300万演算で、無視できる量と考えています。
- `orderSlots` と `drawRange` を GPU で描くこと。CPU の関数は `check.mjs` で確かめましたが、試作の描画はシェーダの中の判定で地上・地下を分けていました。
- 動いている状態の見え方と、年の切り替え時間(0.8 秒)。
- 縦長の画面での飽和(統合後の視覚レビューで確かめます)。
- 色をトークンの sRGB 値で渡したときの見え方。

## 11. 実装後に確かめる項目

Vitest(`reference.js` 相当の純粋関数を `src/` に移したうえで):
1. 枠の予算が 26,206、最大が 887(od.json を読む)。
2. すべての弧・年・補間の値で、Σk clamp(n − k, 0, 1) = 人数 / 100。
3. `arcT` が単調で、`arcT(0)=0`、`arcT(0.5)=0.5`、`arcT(1)=1`。
4. `geometry/arc.js` の `arcPoint` で、ランダムな弧と s について `arcPoint(arcT(s))` までの弧の長さを数値積分し、その割合と s の差が 0.002 以下。
5. 黄金比の並びで、隙間の比が 2.63 以下になり、新しい枠が最大の隙間に入る。
6. 静止の配置がすべて [0.04, 0.96] に入る。
7. `orderSlots` の頂点数(全国: 12,803 + 13,403、東京圏選択: 4,106 + 5,189)と、範囲の中の弧がすべて正しい side であること。
8. ハッシュの固定値: `hash(1) = 1753845952`、`hash(2) = 3507691905`、`hash(3) = 1408362973`。
9. `phaseAt` が [0, 1) に入り、`still` のときは 0 になる。

Playwright:
1. `still=1` で同じ URL を2回撮影し、画素が一致する。
2. 真横の定位置で、粒子の画素が弧の線から ±1px 以内にある(粒子だけを描いた画像と、弧だけを描いた画像を比べる)。
3. `hashcheck.cjs` 相当で、GLSL と JS のハッシュが一致する。
4. 全国(真横、斜め俯瞰、真上)と東京圏選択の画面を撮り、`shots/rec_*.png` と見比べる。

## 12. 設計文書からの変更

- 粒子の位置を、t ではなく弧の長さで決める(`arcT`)。
- 端の薄めを、弧の長さの割合 s で測る。
- 動きを減らす設定の並べ方を、`(k + 0.5)/n` から黄金比の静止配置 `0.04 + 0.92 * fract(k*φ + r_arc)` に変える。
- 粒子の大きさを 2.5 CSS px、不透明度を 0.5 にする。管は使わない。
- 地上と地下を2つの `Points` と `drawRange` で描き分ける。
