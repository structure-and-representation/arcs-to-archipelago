## 2. 指摘

重要度は次の3段階です。
- **A** 公開の前に必ず直す
- **B** 賞の水準に届かせるために直す

### A-1 章の境で2章ぶんの本文が同時に出て、目次・凡例・図に重なる(デスクトップ)

- **何が起きているか**: `.chapter-card` は `position: sticky; bottom: 244px` です。前の章のカードは章の末尾で自然にスクロールして上へ抜け、次の章のカードは画面の下から 244px の位置に貼り付きます。そのため、章の境の約 0.5 画面ぶん、2枚が縦に並びます。
  - 前のカードは目次の下敷きの下へ半透明のまま潜ります(見出しが目次の行間に読める)。
  - 次のカードは凡例の下敷き(`--veil` .88)の下から透けて、凡例の文字と交互に重なります。
- **画面**:
  - `shots/d1440-c1-c-mid.jpg`(左下で、凡例の上に「東京圏の転入超過は、2021年に」が透ける)
  - `shots/d1440-c1-d-boundary.jpg`(2章の本文が凡例と重なる)
  - `shots/d1440-c2-a-start.jpg`(1章の末尾が目次の下に残る)
  - `shots/d1440-c5-e-end.jpg`(ページの最後で、5章の見出しが目次の下に半分潜ったまま止まる)
- **なぜ問題か**: 読む文が、読めない状態で画面に出ます。そのうえ最後の到達点でも見出しが欠けます。「一枚の刷り物」という指針に正面から反します。
- **どう直すか**: 一度に見せるカードを1枚にし、入れ替わるときは不透明度で切り替えます。
  1. `ui/chapters.js` の `renderCurrent(i)` で、現在の章の `section` に `data-current` を付け、ほかの章からは外す。
  2. `ui-chapters.css` に次を足す。
     ```css
     .chapter-card { transition: opacity var(--dur-3) var(--ease-out), visibility 0s linear 0s; }
     .chapter:not([data-current]) .chapter-card {
       opacity: 0; visibility: hidden;
       transition: opacity var(--dur-3) var(--ease-out), visibility 0s linear var(--dur-3);
     }
     ```
  3. あわせて、`.chapter` に `padding-top: 30vh` を足して章の間に間を作る(入れ替わりの瞬間に、2枚の位置が近すぎないように)。
  4. 動きを減らす設定では、時間 0 で切り替える(トークンで自動的にそうなる)。
  5. 目次の下敷き(`.toc::before`)は、この修正の後は不要なら外す。いまは透けた見出しを中途半端に見せる原因になっています。

### A-2 縦画面で本文のカードが図を覆う(390×844、360×640)

- **何が起きているか**: カードの高さが、画面の 45〜60% を占めます(本文 14.5px で 5〜6 行、見出し、補足)。章の境では2枚が重なって、図の 80% 以上が隠れます。360×640 では、2章の図がまったく見えません。カードが図の上にあるので、都道府県の点をタップしてもツールチップが出ません(`mi-tap-pref` で確認。東京の点がカードの下にある)。
- **画面**:
  - `shots/m390-c1-d-boundary.jpg`
  - `shots/m390-c2-a-start.jpg`
  - `shots/m390-c2-c-mid.jpg`(東京圏から南西へ向かう弧が、すべてカードの下にある)
  - `shots/m360-c2.jpg`
  - `shots/m390-c5-e-end.jpg`
- **なぜ問題か**: 縦画面は閲覧の半分以上を占めるはずです。そこで図が見えないのは致命的です。
- **どう直すか**: 縦画面ではカードを sticky にせず、カードとカードの間に図だけが見える区間を作ります。
  - 縦画面のメディアクエリで次のようにする。
    ```css
    .chapter-card { position: relative; bottom: auto; }
    .chapter { justify-content: flex-start; padding-bottom: 75svh; }
    ```
    場面ごとに、カードが一度画面を通り過ぎた後で、図を全面で見せる 75svh を確保します。
  - 場面の切り替えの線(`ANCHOR`)は、縦画面では 0.35 にする。カードの下端が画面の上 1/3 を過ぎたところで、場面が変わります。
  - 補足(`.note`)は縦画面では隠す(`display: none`)。または、表のダイアログの冒頭へ移す。
  - これと合わせて、`figureRegion` の縦画面の y1(高さ − 166)はそのままでよいです。

### A-3 地域を選んだときの構図が破綻している(斜め俯瞰・真上)

- **何が起きているか**: `scene/camera.js` の `viewFor` が、選択地域と主要な相手先を最大 2.5 倍(`SELECTION_ZOOM`)まで拡大し、そのうえで選択地域を領域の内側 18%(`SELECTION_COMFORT`)へ寄せます。その結果、次のことが起きています。
  - 大阪圏・真上(`d-osk-top`): 北海道への弧が画面の上端を突き抜け、上の帯・読み出し(「転入」「転出」の見出し)を横切る。九州への弧は年の折れ線を貫いて画面の下へ抜ける。
  - 東京圏・真上(`d-tokyo-top`、`i-cam-top`): 図が右下に寄り、九州と沖縄は画面の外へ出る。弧が年の折れ線の上を走る。
  - 大阪圏・斜め(2〜3章、`d1440-c3-b-step2`): 弧が画面の左右の端で切れ、左の本文の柱の下まで入り込む(千葉・神奈川のラベルが本文の右端に接する)。
  - 東京圏・斜め(2章、`d1440-c2-a-start`、`d-c2-ink`): 沖縄への弧が読み出しの「差引 +145,576」を横切って右端で切れる。
  - 東京都・斜め(`d-tky-obl`): 同じく右端で切れる。
  - 1024×768(`w1024-c3`): 弧が本文の上を通る。
- **なぜ問題か**: 以前ユーザーが指摘した「図が右上の読み出しと重なる」問題が、真上以外の構図と、真上の別の地域で再発しています。量を粒子の数で読ませる作品で弧が画面の端で切れると、どの相手先が切れたのかを読者が知る方法がありません。誠実さの面でも問題です。
- **どう直すか**:
  1. 拡大の上限をカメラごとに分ける。
     - 真上は `SELECTION_ZOOM = 1`(拡大しない。地図として全体を見せる)。
     - 斜め俯瞰は 1.4。
  2. 寄せた後の検査を足す。`slide` の後で、47都道府県と、選択地域に関わるすべての弧(`figureCloud` の点)を画面に射影し、画面全体(0〜幅、0〜高さ)からはみ出す量を求める。はみ出していれば `scale` を 0.9 倍ずつ下げて、計算し直す(最大 6 回)。
     - 「領域」でなく「画面」で判定するのは、多少 UI の下へ入るのは許し、画面の外へは出さないためです。
  3. 読み出しと年の切り替えの後ろに下敷きを敷く(本文と同じ、縁をぼかした `--veil`)。
     ```css
     #selector .sel::before {
       content: ""; position: absolute; z-index: -1; inset: -24px -40px -32px -64px;
       background: var(--veil);
       mask-image: linear-gradient(270deg, #000 75%, transparent),
                   linear-gradient(180deg, #000 calc(100% - 32px), transparent);
       mask-composite: intersect;
     }
     #timeline::before {
       content: ""; position: absolute; z-index: -1; inset: -40px -24px -36px;
       background: linear-gradient(to top, var(--veil) calc(100% - 40px), transparent);
     }
     ```
  4. 2. を入れても相手先が画面の外に残る場合は、画面の端に「→ 沖縄 1,507」のような小さな印を `--fg-3` で出す(C で可)。

### A-4 URL から直接入ると、自由探索の章で前の章のカードが目次に重なる

- **画面**: `shots/d-osk-top.jpg`、`shots/d-tokyo-top.jpg`。`sel=` や `cam=` を指定して開いた画面は、すべてこの状態でした。
- **何が起きているか**: `initialScene` が自由探索の場面の位置(`step + 0.05`)へスクロールします。その位置では、4章のカードがまだ画面の上部に残っています。
- **なぜ問題か**: 共有された URL から入った読者が最初に見る画面です。
- **どう直すか**: A-1 の修正で解決します。A-1 を入れないなら、はじめのスクロール位置を、その章のカードの上端が目次の下端(y 200)より下に来る位置にします。具体的には `g.top + (g.height / g.steps) * (step + 0.5) - innerHeight * 0.5` です。

### A-9 真横の「弧の高さ=距離」は誤り

- **画面**: `shots/d1440-c1-a-start.jpg` の凡例。真横の全画面に出ています。
- **何が起きているか**: 真横(morph 0)では、弧の高さは並び順の隔たり(添字の差 × STEP)に比例します。地理上の距離ではありません。たとえば北海道→青森と、鹿児島→沖縄は、並びでは同じ「隣」なので同じ高さですが、実際の距離は大きく違います。
- **どう直すか**: `legend.height` を、カメラ(または morph が 0.5 より小さいか)で切り替えます。
  - 真横: 「弧の高さ=並びの上の隔たり」(英語は「Arc height = gap in the list」)
  - それ以外: 「弧の高さ=距離」
  - 文言は文案担当が strings.md に足す。

### B-1 斜め俯瞰で、地上(転入)と地下(転出)の束が区別できない

- **画面**: `shots/d-c2-ink.jpg`、`shots/d1440-c2-a-start.jpg`。東京圏の転入と転出が一つの扇に見えます。凡例の「上下の厚みの差が、転入超過・転出超過」を画面で確かめられません。
- **なぜ問題か**: 選択時の符号化の核です。
- **どう直すか**:
  1. 地下の弧の線を破線にする。シェーダで弧の長さに沿って、`fract(s * 60.0) < 0.5` のとき α を 0 にする。凡例の線画(下の弧は点線)と揃います。**粒子の不透明度は地上と地下で変えない**(量の見え方を変えないため)。
  2. 選択時の斜め俯瞰の仰角 `SELECTION_OBLIQUE.elevation` を 0.72 から 0.45 前後へ下げ、地面の上下の厚みが見える角度にする。lean は 0.25 のまま。0.40、0.45、0.55 で撮り比べて決めてください。
  3. 地面(陸地の面、§5)を地上の層と地下の層の間に置くと、上下の手がかりになります。ただし §5 の注意を守ってください。

### B-2 密な場所のラベルが、灰色のにじみになって読めない

- **画面**: `shots/crop-labels-halo-2x.png`(2倍。東京・神奈川・埼玉・静岡・愛知・大阪の縁取りが、墨の弧の上で灰色の雲になる)、`shots/crop-m390-labels.jpg`(縦画面では、文字が読めない白い四角が並ぶ)、`shots/d1440-c1-c-mid.jpg`。
- **何が起きているか**: 6重の `text-shadow` は、文字の周りを紙色で塗り切れません。縁が半透明のぼかしになり、墨の弧と混ざって中間の灰色になります。文字は `--fg-3`(.64)なので、その灰色の上ではコントラストが 2:1 前後まで落ちます。

## 5. 陸地を面で描くときの注意(並行作業の担当へ)

1. **量の見え方を変えない(品質の基準 8 章)。** 陸地の面を、地下の層と地上の層の間に半透明で敷くと、地下の粒子(転出)だけが面の下で薄く見えます。転入と転出の比較が、面の不透明度の分だけ転入に有利に歪みます。
   - 面は地下の層より下に描く(描く順序の 2 を、地下の弧 0 の前へ)。
   - 上下の手がかりは、地下の弧の線の破線(B-1)で与える。
   - どうしても面を間に置くなら、地下の粒子だけを面より上の描画順で描き、線だけを面の下に置く。
2. **小さな島が粒子に見える。** いまの海岸線でも、九州・沖縄の周りの小島が直径 2〜3px の点になり、1粒(直径 2px)と区別できません(`d-osk-top`、`d-tokyo-top`)。画面上の面積が 12px² 未満の島は描かないか、粒子と違う形(輪郭線だけ)にしてください。
3. **ラベルの縁取りと面の色。** B-2 で、ラベルを紙色の札にすると、陸地の面の上では札が四角く浮きます。札の地を面と同じ色(紙と陸地の不透明度を合成した色)にできるよう、面の色をトークン(例 `--gl-land`)として CSS からも読めるようにしてください。
4. **真横では面を出さない。** morph 0 では面が線に潰れて、弧の網の中心に濃い水平線が出ます。`smoothstep(0.6, 1.0, morph)` で出すことを推奨します(B-4 と同じ値)。
5. **紙の色で抜く県境の太さ。** 斜め俯瞰では奥の県境が短縮して消えます。県境の線幅は画面の px で一定(0.75 CSS px 以上)にしてください。墨のテーマでは「紙の色で抜く」は「墨の地の色で抜く」になるので、`--bg` を使ってください(`--gl-fg` ではない)。
6. **選択地域の面。** 朱は一点だけ、という指針を守るため、選択地域の面に朱を敷かないでください。強調するなら、面の不透明度を 1.5 倍にする程度にとどめます。
7. **面の濃さの上限。** 粒子の不透明度の上限(.60)と面の濃さが近いと、地面の上の疎な粒子が沈みます。面は fg の .05〜.08(紙のテーマ)、.06〜.10(墨のテーマ)に抑えることを推奨します。
